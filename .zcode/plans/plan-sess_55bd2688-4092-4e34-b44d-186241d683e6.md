# Fix sparse ordering + editor create-row placement (branch `aligner-order-rework`)

## Root causes (all verified in code)

1. **Sequential orders at creation** — `laravel/app/Classes/SentenceSplitter.php` (the file-upload → entity-creation path) writes `1,2,3,4,5…`: `appendSentenceToBatch()` does `$order++` then `'order' => $order` (lines 250/257). Every other creation path already uses `SparseOrderService` (importer, add-sentence, Filament manager) — this is the only one that doesn't.
2. **New meaning-match rows jump to the top** — `resources/js/Pages/Alignments/Show.jsx` `onCreateBelow()` (lines 426–452) computes `insertAt` **inside** a `setData` updater but reads it synchronously at line 451. React 19 only evaluates a state updater eagerly on the *first* dispatch after mount; on every later dispatch it's deferred, so `insertAt` snapshots as `0`, and `applyMutation()` splices the real server row at index 0 → top of the page until refresh. (The server assigns a correct order — refresh shows the right place.)
3. **Full 0,1024,2048 renumber on reorder** — a consequence of #1: with dense orders (gap ≤ 1), `SparseOrderService::between()` returns `null` (SparseOrderService.php:34) and `orderForInsertAfter` falls through to `rebalanceItems()` → renumbers the whole list, so the reorder endpoints write every row. Those endpoints are already minimal-write by design; once orders are sparse from creation, a reorder touches only the moved row (midpoint of neighbours).

## Changes

### 1. `laravel/app/Classes/SentenceSplitter.php` — sparse orders at creation
- Inject `SparseOrderService` (constructor promotion; the job resolves the splitter via the container, no direct `new` anywhere).
- In `appendSentenceToBatch()`: write `'order' => $this->sparseOrder->initial($order)` and increment `$order` after use → **0, 1024, 2048…**; `$order` stays the sentence count so `$stats['sentences']` is unchanged.

### 2. `laravel/resources/js/Pages/Alignments/Show.jsx` — anchor-based insertion
- Change `runMutation`'s optional second argument from a numeric `insertAt` to the **anchor row id**; `onCreateBelow` passes `row.id`.
- In `applyMutation`, compute the insert position at response time: find the anchor row's index in the current rows list and splice the new row after it (append at end as fallback if the anchor isn't found). Remove the `insertAt` side effect from the `setData` updater (updater becomes pure).
- Reset the anchor ref when a mutation fails so a failed create can't leak a stale anchor into the next mutation.

### 3. Drive-by crash fix: `laravel/app/Jobs/AlignEntitySentences.php:1058`
- Remove `'order' => 0` from the junction `create()` — the junction tables' `order` column was dropped by migration `2026_08_20_131441_drop_order_from_junction_tables`, so this line throws an SQL error whenever the original-side skip-run drain executes.

### 4. One-time rebalance of existing data
- `docker exec ext_app_laravel php artisan entity-orders:rebalance` — converts existing dense sentence lists to 0,1024,2048 (writes only changed rows, two-phase parking, safe under the unique index). The daily schedule already runs it; running it once makes edit-time minimality immediate on dev. For prod, run at next deploy or let the daily schedule handle it.
