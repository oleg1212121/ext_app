# Recommendations

The navbar's **Recommendations** item (top-level, after Resources) opens
the personalized reading queue: the viewer's readable, completed texts
grouped under their works, filtered to the texts whose **Word knowledge**
snapshot ([entities](/domains/entities.md), ADR
[0074](../../docs/adr/0074-entity-word-knowledge.md)) sits at or above a
threshold (default 90%), ordered **least known first** — an easy-read
finder. For the domain language see `CONTEXT.md` → *Recommendations
Context*. Decision record:
`docs/adr/0075-recommendations-page.md`.

## Read-only pass over the snapshot table

The page **never computes a score and never writes**: it only reads
`user_entity_word_knowledge`, so a text appears the first time the viewer
opens its detail page (where `EntityWordKnowledgeService::ensure` creates
the snapshot). Texts never opened never appear — this is a re-ranking of
the viewer's reading history, not a discovery tool (ADR 0075 decision 2).

## Filter semantics

- **Knowledge** is a *minimum* threshold, clamped to 0–100, default 90;
  a non-numeric `?knowledge=` falls back to 90. Listed texts span
  threshold → 100, ascending: comprehensible input with the most headroom
  first.
- **Language** defaults to `en`; unknown or disabled codes 404 (the
  reader's resolution rule via `Language::enabled()`).
- **Search** `?q=` (escaped ilike, the Library convention) matches work
  title/author or the *qualifying* texts' name/label — a hit surfaces its
  work; a text that fails the threshold never does.
- **Unrankable texts are excluded silently**: no non-null snapshot for
  this viewer, word list mid-rebuild or never built (the guard mirrors
  `EntityWordKnowledgeService::refreshStale` — keep the two definitions in
  step), or a non-completed upload. Read access applies via
  `EntityAccessService::readableQuery`.

## Page structure

`RecommendationsController::index` runs the qualifying filter twice: once
grouped per work (`MIN(score)`, via a `joinSub` so `paginate()`'s count
stays correct) for the 15-per-page work rows, ordered by that minimum
ascending (ties: title), and once for the page's works' qualifying texts,
ordered score-then-name and grouped in PHP. The React page
(`resources/js/Pages/Recommendations/Index.jsx`) renders one GET form
(search + knowledge number input + language select + **Apply**) in the
Library list idiom, stacked work cards with expandable text dropdowns
(each text row carries name/label, language, sentence count and the
rounded percentage), `LinkPagination`, and the empty states: no snapshots
yet (pointer to the Library; plus the word-test hint when the viewer has
no `user_word` rows at all, the `has_no_familiarity` prop) vs. no match
for the filters. Reuses the `entities.word_knowledge*` strings.
